# Security

Do not place credentials, transcripts, local databases, provider errors containing private payloads, or reviewer job results in public issues. For a suspected vulnerability, use GitHub private vulnerability reporting when enabled. If unavailable, report only a non-sensitive request for a private contact channel.

Report affected commit, Windows/tool versions, bounded synthetic reproduction, expected and observed behavior, and remediation ideas. Do not upload live keys or private project data.

For accidentally published credentials, revoke or rotate first, then remove exposed content from Git history and follow GitHub's sensitive-data remediation guidance. Removing the latest file alone does not remove earlier copies.
